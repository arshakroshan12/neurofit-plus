KEY DESIGN PATTERNS
================================================================================

STATE MACHINE (8 States)
├── ONBOARDING
│   └─ User answers: proceed or ask why
│      ├─ PROCEED → FOCUS_SELECTION
│      └─ WHY → FATIGUE_EXPLANATION
├── FATIGUE_EXPLANATION
│   └─ Bot explains why fatigue matters
│      └─ User ready → FOCUS_SELECTION
├── FOCUS_SELECTION
│   └─ Bot asks: what body part to focus on?
│      └─ User picks → WORKOUT_DELIVERY
├── WORKOUT_DELIVERY
│   └─ Bot shows filtered workouts
│      ├─ PROCEED → SUMMARY
│      ├─ ADJUST → ADJUSTMENT
│      └─ CHANGE_FOCUS → FOCUS_SELECTION
├── DOUBT_HANDLING
│   └─ Bot addresses safety concerns
├── ADJUSTMENT
│   └─ Bot adjusts recommendations
│      ├─ PROCEED → SUMMARY
│      └─ CHANGE_FOCUS → FOCUS_SELECTION
└── SUMMARY
    └─ Workout confirmed, session ends
       └─ User wants new session → ONBOARDING

INTENT DETECTION (7 Types)
├── WHY (user asks "why", "explain", "tell me")
├── SAFE (user asks "safe", "okay", "hurt", "injury")
├── ADJUST (user says "adjust", "change", "harder", "easier")
├── CHANGE_FOCUS (user says "other area", "try different", "switch")
├── PROCEED (user says "yes", "okay", "go", "ready", "start")
├── EXPLAIN_FATIGUE (user mentions "fatigue", "tired", "exhausted")
└── GENERAL (fallback - anything else)

FATIGUE LOGIC (Local, Deterministic)
├── LOW fatigue (< 0.35) → Show all intensities, encourage challenge
├── MODERATE fatigue (0.35-0.70) → Show medium intensity, include rest
└── HIGH fatigue (≥ 0.70) → Recovery ONLY, skip focus selection, non-negotiable

SESSION MEMORY (Avoids Repetition)
├── selectedFocusArea (remember what user picked)
├── lastIntensity (track previous workout intensity)
├── selectedWorkouts (cache recommendations)
├── askedAboutFatigue (don't re-explain)
└── askedAboutFocus (don't re-ask)

WHAT MAKES THIS IMPLEMENTATION SPECIAL
================================================================================

1. PROACTIVE vs REACTIVE
   Before: Bot responds to user input (passive)
   After: Bot leads conversation (proactive)

2. STATE-DRIVEN vs INPUT-DRIVEN
   Before: Process input → output response
   After: Current state + user input → next state + response

3. INTENT-AWARE vs KEYWORD-GUESSING
   Before: Simple pattern matching
   After: Semantic intent detection with 7 distinct intents

4. MEMORY-FULL vs STATELESS
   Before: Each message independent
   After: Session memory prevents repetition

5. SAFE vs PERMISSIVE
   Before: User could ask for intense workouts while fatigued
   After: High fatigue → recovery ONLY (enforced)

6. EXPLAINABLE vs OPAQUE
   Before: Magic happens inside, hard to debug
   After: Clear state transitions, easy to trace flow

7. SCALABLE vs BRITTLE
   Before: Hard to add new conversation paths
   After: New intents = add pattern + add transition
